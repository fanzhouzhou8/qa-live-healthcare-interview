## 2. 背景与目标

### 2.1 背景

当前问诊页（`Consultation.vue`）使用「姓名 + 生日」弱校验进入问诊，任意输入即可自动建档，无法形成稳定账号体系，也不利于后续扩展。

### 2.2 目标

1. 问诊用户可通过 **用户名 + 密码** 登录后使用问诊功能
2. 患者账号数据存储在 MySQL，由 `qa-service-user` 提供登录 API
3. 前后端联调完成，可用测试账号演示完整登录流程

### 2.3 非目标（Out of Scope）

- 不做短信验证码、第三方 OAuth、找回密码
- 不做密码加密升级为 BCrypt（本迭代明文比对，与现有医生账号一致，便于演示）
- 不做问诊问题数据的 MySQL 迁移（问题仍走前端 store）
- 不改造医生登录流程

## 3. 用户与场景

### 3.1 目标用户

| 用户角色 | 描述 |
|----------|------|
| 问诊用户（患者） | 需要登录后提交问题、查看自己的问诊记录 |

### 3.2 核心场景

1. 患者打开「问诊」页，输入用户名和密码，登录成功后进入问诊门户
2. 用户名或密码错误时，看到明确错误提示，不能进入问诊门户
3. 已登录用户可点击「退出登录」回到登录表单

---

## 4. 需求说明

### 4.1 功能需求

| 编号 | 需求描述 | 优先级 | 验收标准 |
|------|----------|--------|----------|
| FR-01 | 问诊页提供用户名、密码登录表单 | P0 | 字段、校验、登录按钮齐全 |
| FR-02 | 调用后端登录接口校验账号 | P0 | 正确账号可登录；错误账号提示失败 |
| FR-03 | 登录成功后展示问诊门户（原有功能保留） | P0 | 可提交问题、查看问题列表 |
| FR-04 | 支持退出登录 | P0 | 退出后回到登录表单，会话清空 |
| FR-05 | 提供可演示的种子测试账号 | P0 | 文档/页面提示至少 1 个测试账号 |

### 4.2 交互与界面

- **入口**：`/consultation`（及带医生参数的诊室路径）未登录时展示登录卡
- **表单字段**：
  - 用户名（必填）
  - 密码（必填，密文输入）
- **按钮**：登录
- **提示**：展示测试账号（如 `patient_zhaoming` / `123456`）
- **成功**：Toast「登录成功」，进入问诊门户
- **失败**：Toast「用户名或密码错误」

### 4.3 业务规则

1. 仅已存在于数据库的患者账号可登录，不在前端自动注册
2. 登录成功后前端保存当前患者信息（id、username、name 等），用于问诊门户展示与提问
3. 接口响应不得返回密码字段
4. 登录态本迭代仅保存在前端内存（刷新需重新登录），不做 Token/JWT

## 5. 数据与接口

### 5.1 数据模型

表名：`patient`

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | VARCHAR(32) | 是 | 主键 |
| username | VARCHAR(64) | 是 | 登录用户名，唯一 |
| password | VARCHAR(128) | 是 | 登录密码（演示用明文） |
| name | VARCHAR(64) | 是 | 显示姓名 |
| birthday | DATE | 否 | 生日 |
| phone | VARCHAR(32) | 否 | 手机号 |
| gender | VARCHAR(16) | 否 | 性别 |
| created_at / updated_at | TIMESTAMP | 是 | 审计字段 |

种子账号示例：

| username | password | name |
|----------|----------|------|
| patient_zhaoming | 123456 | 赵明 |
| patient_sunli | 123456 | 孙丽 |

### 5.2 接口清单

| 方法 | 路径 | 说明 | 请求体 | 响应 |
|------|------|------|--------|------|
| POST | /api/patients/login | 患者登录 | `{ "username": "", "password": "" }` | 成功：`{ code:0, message:"ok", data:{ id, username, name, birthday, phone, gender } }`；失败：`{ code:401, message:"用户名或密码错误", data:null }` |

### 5.3 错误码约定

| code | 含义 |
|------|------|
| 0 | 成功 |
| 401 | 用户名或密码错误 |
| 400 | 参数缺失 |

## 8. 测试要点

1. 正确用户名密码 → 登录成功，显示姓名与问诊门户
2. 错误密码 → 提示失败，不进入门户
3. 空用户名/空密码 → 前端表单校验拦截
4. 退出登录 → 回到登录表单
5. 登录后仍可提交问题、查看问题列表（沿用原前端逻辑）
